# Stop hook writes no done marker when the worker's cwd is a repo subdirectory

- **Symptom:** two analyst asks exited 3 although a full report existed. The Stop hook ran cleanly (about 30 ms), but no `.harness/done/analyst.<ask-id>` appeared, so the 30 s idle grace gave up. The hint ("respawn") is wrong here.
- **Cause:** the worker ran `cd <subdir> && …` in Bash, and Claude Code kept that in-repo cwd. The hook's `cwd` was the subdir, `enter_root` changed into it, and `mark_done` read the relative `.harness/asks/<role>.current`, found none and returned 0 silently. This is not a stale-hook respawn case.
- **Next time:** `enter_root` should go to `git rev-parse --show-toplevel`, and `mark_done` should warn on stderr. `cmd_stop` shares this path.
- **Evidence:** asks 1792643421-12588-9450, 1792644961-69735-4647; bin/harness-verify:32-34, :243, :258; bin/harness:1083. In transcripts 8884b1fc and b7ce5751 the cwd at `stop_hook_summary` is the subdir.

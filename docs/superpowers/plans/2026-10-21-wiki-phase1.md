## Task A — CLAUDE.md (implementer)
Project `CLAUDE.md` ≤60 lines: what the repo is (one paragraph), directory map (bin/, claude/agents, claude/hooks, claude/skills, tests/, docs/), test command `./install.sh --test`, bash 3.2 rule, and a "Wiki" section: where it lives, frontmatter schema, "read docs/wiki/index.md first; open pages only when relevant", promotion ladder (inbox → page → .claude/rules or agent prompt line after 2+ recurrences → SKILL.md for repeated procedures → hook/test for must-hold rules; promotions only via human-approved PR), and "do not record what can be derived from code".

## Task B — Inject the index at session start (implementer)
`claude/hooks/conductor-resume.sh` (SessionStart): after progress.md, append the `status: active` lines of `docs/wiki/index.md` (lines containing `(active,`), capped at 2048 bytes total for the wiki part (truncate with a "… see docs/wiki/index.md" line). If no index, nothing. Workers: do the same for worker sessions if the worker SessionStart path exists; otherwise rely on CLAUDE.md pointer. Tests.

## Task C — `## Learned` report section → inbox (implementer)
Report contract (wherever it is defined: agent prompts + finish_report in bin/harness): optional `## Learned` section, ≤2 bullets, each must cite evidence (ask-id, commit, file:line or log). When `harness ask`/`report` collects a report with a non-empty `## Learned`, copy those bullets to `docs/wiki/inbox/<date>-<role>-<ask-id>.md` with a small header (role, ask-id, date). Skip if the section is missing or only "none". Do not print anything extra to the conductor beyond one line `wiki: 1 lesson queued in docs/wiki/inbox/...`. Tests.

## Task D — `harness wiki-lint` (implementer)
Mechanical checks only, exit 1 on any error, print `file: problem` lines:
- every page under docs/wiki (except index.md, log.md, inbox/) has the frontmatter keys above with valid values;
- every page is listed in index.md exactly once and every index link resolves;
- index.md ≤80 lines; pages ≤150 lines;
- inbox items older than 14 days → warning (not error);
- banned fluff phrases warning ("works well", "잘 동작", "very important", "중요하다").
Wire into `./install.sh --test` as a lint step over the real docs/wiki so a bad page fails CI. Tests with fixture dirs.
